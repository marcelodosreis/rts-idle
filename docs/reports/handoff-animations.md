### Facts to rely on
- **Tile grid: 64×64 px** (confirmed — `terrain.tileset.color1` manifest:
  `cellW/cellH 64`, 9×6 grid).
- **Animation speed: 10 fps = 100 ms/frame default** (manifest durations are
  `100`; `createAnimation` falls back to `?? 100`).
- Frame cell = square of the strip height (units 192 px, Lancer 320, trees 256,
  resources 128, water foam 192); frames = `width / height`. Manifest is
  generated by `pnpm assets:prepare` (writes `apps/web/public/assets/` —
  gitignored, license-pending, ADR-015).
- Unit sprites: `packages/renderer/src/unit-layer.ts` — `AnimatedSprite` per
  unit + shadow decal, fallback circle if art missing. Renderer drives frames
  manually via `app.ticker` (`advanceAnimation(ticker)`), not Pixi shared
  ticker.
- Curated asset set (52): Pawn/Warrior/Archer × blue/red/purple/yellow
  (idle/run/attack + arrow), terrain tileset/water/shadow/rock, explosion FX,
  UI bars/panels/buttons. Full inventory + integration ideas:
  `docs/assets/capabilities.md`.

### Known issues to fix here
1. **Animation advance is flaky under a throttled headless ticker** — the
   visual e2e (`tests/e2e/visual-feedback-base.spec.ts`) originally asserted a
   frame changes within a poll; it stalled at the last frame and timed out. It
   was relaxed to a deterministic "art loaded" check. Make frame advancement
   robust (deterministic clock or reliable ticker), then restore a
   frame-advances assertion.
2. **Visual review** — inspect `apps/web` at `http://localhost:5173` with
   `pnpm dev` running and the server at `:8080`. Check: unit cell scale
   (SPRITE_SCALE = 0.5), anchors at the feet, flip by direction, shadow decal,
   idle/run swap on MOVE, terrain rendering. Screenshot was captured but this
   model cannot view images.
3. **Hit-area tuning** — `Circle(0, -12, 26)` per unit container: keep clicks
   at the unit's feet selecting that unit and drags starting ~25 px away on
   empty ground (box select). Do not regress the selection/box e2e specs.
4. **Attack animation swap** — the `attack` frames exist in the manifest but
   are not yet used (combat systems land in the continuation). Pre-wire the
   animation state (idle/run/attack) so the continuation can drive it.
