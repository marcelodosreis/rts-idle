# P3.07.01 - Vision and Memory

## Task

- ID: `P3.07.01`
- Objective: Give each player deterministic visible, explored, and unknown map state and expose it through the match screen.
- Why: The player must make decisions from the information available to that player, not from hidden world state.
- Scope: `packages/simulation`, `packages/protocol`, `apps/server`, `packages/renderer`, `apps/web`, and focused simulation/protocol/browser tests.
- Non-goals: Full fog styling, filtered event redesign, targeting changes, projectiles, and area damage.

## Approved decisions

- All current units and buildings use an eight-tile circular vision radius.
- All four `PlayerId` slots have independent visibility and memory state; the
  current browser session continues to control player `0`.
- The first slice includes the minimum entity/resource filter required to avoid
  hidden-state leakage. `P3.08.01` extends this into the complete protocol
  filtering contract.
- Explored tiles, previously observed buildings, and previously observed
  resources are retained as player-specific memory.
- Static map terrain remains public and is visually dimmed by fog; dynamic
  occupancy and resource state remain private.

## Contract

- Vision is derived from owned units and buildings using the authoritative vision values.
- The simulation stores player-specific visible and explored state without changing hidden world state.
- Visibility updates are deterministic and snapshot-safe.
- The match screen exposes a minimal vision state: current vision, retained explored area, and unknown area.
- Natural interaction: select a controlled unit and move it to reveal a previously unknown map region.
- Success feedback: the newly visible region and its explored memory are visible in the match screen.
- Blocked/error feedback: invalid or unavailable vision data is rejected without revealing hidden entities.
- Browser target: `tests/e2e/match/vision-memory-playable.spec.ts` through the real server.

## Design

Keep visibility computation in simulation and projection/filtering at the server boundary. The renderer and web client only present the observation. Use typed player and visibility registries; do not expose mutable simulation state.

## Tests and validation

- Unit tests for deterministic visibility, explored-memory persistence, and bounds.
- Simulation tests for snapshot/restore and equivalent hidden worlds.
- Protocol tests for independent observation copies.
- Browser E2E in Chromium and Firefox covering reveal, retained exploration, and hidden-entity absence.
- `pnpm run verify`
