# P3.07.02 - Vision Radius Tuning

## Task

- ID: `P3.07.02`
- Objective: Reduce the authoritative vision radius from eight tiles to four tiles while keeping the footprint a deterministic circular mask.
- Why: The current vision footprint is too large for readable local exploration and reveals too much of the map at once.
- Scope: `packages/simulation`, simulation snapshot/versioning, current vision/fog browser fixtures, and task documentation.
- Non-goals: Fog artwork or gradients, new visibility sources, targeting rules, minimap work, multiplayer, projectiles, and area damage.

## Contract

- Every current unit and owned building reveals a radius of exactly four tiles.
- Visibility uses the existing Euclidean tile-center rule `dx² + dy² <= radius²`.
- Multiple sources continue to reveal the union of their circular masks.
- Visible, explored, unknown, memory, filtered entities, filtered resources, and filtered events retain their existing semantics.
- The wire message shape does not change; malformed fog remains rejected by the existing protocol guards.
- Canonical snapshots serialize radius `4`; the simulation version increments to reject incompatible pre-tuning snapshots.
- Natural interaction remains selecting a controlled unit and moving it to reveal a local region.
- The match screen shows a smaller current vision area, retains explored terrain, and keeps hidden entities/resources absent until revealed.
- Browser E2E continues through the real server in Chromium and Firefox; tests reveal targets by moving a controlled unit before interacting with them.

## Design

Keep radius ownership in `VISION_RADIUS_TILES` and make the snapshot decoder
validate that same constant instead of duplicating a numeric literal. Keep the
server-side projection and renderer boundaries unchanged. Add boundary tests for
cardinal and diagonal tiles so the smaller footprint remains a regular circle
on the deterministic tile grid.
