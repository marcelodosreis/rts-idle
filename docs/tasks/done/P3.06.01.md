# Task Packet: P3.06.01 Collision and Avoidance

## Task

- ID: `P3.06.01`
- Objective: replace straight-line movement with deterministic navigable movement
  that respects building and unit collision in the real match flow.
- Why: the player needs a meaningful movement slice around walls and buildings,
  with authoritative progress and a visible blocked/unreachable result.
- Scope: simulation movement/navigation integration, movement feedback event and
  protocol guard, match HUD feedback, real-server browser coverage through the
  unified `regression` fixture, and focused simulation/determinism tests.
- Non-goals: fog of war, filtered observations, projectiles, area damage, AI,
  multiplayer, or work after `P3.06.01`.

## Contract

- The frozen 12-system pipeline remains unchanged. Navigation work stays in the
  existing `orders` substep and movement remains the next pipeline system.
- MOVE, PATROL, ATTACK_MOVE, GATHER, DEPOSIT, BUILD, and producer rally movement
  retain their existing authoritative command semantics.
- A moving unit uses the deterministic navigation grid to route around blocked
  building footprints. The route is persisted in canonical movement state so a
  snapshot/restore continuation is equivalent.
- Building collision tests the traversed segment, not only the final point.
  Mobile-unit collision uses the P3.05 spatial index and a fixed logical unit
  radius; a fixed avoidance candidate sequence is used before declaring a tick
  blocked.
- Units never cross a building footprint, teleport, overlap another unit to
  clear a choke, or invoke a fresh A* search every frame.
- Persistent blockage emits one deterministic `movementBlocked` event for the
  affected unit. The event distinguishes `COLLISION` from `UNREACHABLE` and is
  carried through the existing snapshot event path.
- The match screen remains the interaction surface: select units and right-click
  a destination near/behind a building. The player sees movement progress and a
  visible HUD message when movement is blocked or unreachable.
- The real server path is covered in Chromium and Firefox through the unified
  `regression` scenario. The former isolated `movement-collision` demo was
  removed after this coverage was migrated.

## Design

- Movement geometry and route state stay authoritative in `packages/simulation`;
  the renderer and web only project observations/events.
- Route fields are encoded with the existing `Movement` component codec and the
  simulation version is bumped because canonical state semantics change.
- The spatial index remains a derived pure structure. Collision narrow-phase
  helpers use integer fixed coordinates and deterministic candidate ordering.
- The protocol adds a typed event registry entry and guard branch; no loose
  domain strings or compatibility aliases are introduced.

## Automated Gameplay Fixture

- Every automated player-facing gameplay E2E starts from
  `scenario=regression`; tests may vary authoritative options such as
  `aggression` and `sprites` when the behavior requires it.
- Retained demo scenarios remain manual-only; no isolated movement-collision
  scenario is part of the catalog or the automated gameplay fixture set.
- Unit, integration, simulation, and determinism tests remain scenario-free and
  use their owning deterministic fixtures instead of loading a demo scenario.
