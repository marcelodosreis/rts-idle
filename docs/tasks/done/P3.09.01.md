# P3.09.01 - Targeting and Pursuit

## Task

- ID: `P3.09.01`
- Objective: Make target acquisition and pursuit obey visibility, spatial queries, and deterministic loss-of-vision rules in a playable match.
- Why: Units must not gain hidden coordinates or continue pursuing information the player cannot observe.
- Scope: `packages/simulation`, `packages/protocol`, `apps/server`, `packages/renderer`, `apps/web`, and browser/simulation tests.
- Non-goals: Projectiles, area damage, AI behavior, and new unit content.

## Contract

- Target acquisition uses visible candidates and stable priority, distance, and entity-ID tie-breaks.
- `ATTACK` pursues while the target is visible and valid, then uses only the last known position and stops.
- `ATTACK_MOVE` acquires only visible candidates, resumes its route after a visible target leaves range, and uses only the last known position after vision loss.
- A target that reappears is not reacquired automatically; a new command is required.
- `HOLD` never pursues a target outside attack range.
- Player and authored orders obey the same visibility rules.
- Natural interaction: select a combat unit and issue attack or attack-move against a visible enemy.
- Success feedback: the unit acquires, attacks, and visibly pursues the target.
- Blocked/error feedback: hidden or invalid targets are rejected; loss of vision produces the visible `Alvo perdido` stopped state.
- Browser target: `tests/e2e/match/targeting-pursuit-playable.spec.ts` through the real server.

## Design

Use the authoritative spatial index and player visibility state. Keep target selection and order mutation in simulation systems; expose only legal observation and order feedback to the client.

## Tests and validation

- Unit tests for tie-breaks, visibility checks, and last-known-position rules.
- Simulation and determinism tests for pursuit and loss of vision.
- Browser E2E in Chromium and Firefox covering attack, pursuit, target hiding, and feedback.
- `pnpm run verify`
