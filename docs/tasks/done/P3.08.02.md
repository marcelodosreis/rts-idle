# P3.08.02 - Fog Rendering

## Task

- ID: `P3.08.02`
- Objective: Render visible, explored, and unknown map states as readable fog in the match screen.
- Why: The player needs immediate visual feedback about what is currently known and what is not.
- Scope: `packages/renderer`, `apps/web`, match scenario fixtures, and browser tests.
- Non-goals: New visibility rules, hidden-state computation in the browser, targeting, projectiles, and area damage.

## Contract

- Fog is a projection of filtered observations, never a second gameplay model.
- Current vision is clear, explored memory is retained, and unknown terrain is obscured.
- Natural interaction: move a controlled unit across the map and watch fog transitions.
- Success feedback: fog changes in the same tick window as the authoritative observation.
- Blocked/error feedback: missing or invalid visibility data fails closed to unknown presentation.
- Browser target: `tests/e2e/match/vision-memory-playable.spec.ts` through the real server.

## Design

The renderer consumes only protocol observations and owns presentation state. Keep fog geometry separate from gameplay rules and preserve the established PixiJS layer boundaries.

## Tests and validation

- Renderer tests for visible, explored, unknown, resize, and observation replacement states.
- Browser E2E in Chromium and Firefox covering fog transitions and hidden-entity absence.
- Responsive match-screen smoke coverage.
- `pnpm run verify`

## Player-facing completion

- [x] The player can reach fog through the match screen.
- [x] The player can reveal and revisit terrain naturally.
- [x] Visible, explored, and unknown areas are visually distinct.
- [x] The real server path is covered by browser E2E.

## Acceptance and stop conditions

- [x] Fog is strictly derived from observations.
- [x] Hidden entities are not rendered.
- [x] The player-facing flow and E2E pass in both required browsers.
