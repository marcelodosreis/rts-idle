# P3.04.01 - Group Destinations

## Task

- ID: `P3.04.01`
- Objective: resolve deterministic, navigable, distinct formation destinations for a sorted group of units.
- Why: multi-unit commands need stable targets before path requests and collision can be integrated.
- Scope: simulation formation domain, pathfinding-grid queries, focused unit/integration tests, and deterministic replay coverage.
- Non-goals: movement routing, collision radii, local avoidance, spatial indexing, protocol/UI feedback, or browser gameplay.

## Contract

- Unit IDs are sorted numerically before assignment; input order never changes the result.
- Candidate positions follow the existing deterministic clockwise spiral around the clicked tile.
- A candidate is accepted only when it is in bounds, walkable, and distinct from already accepted tile targets.
- Blocked or duplicate candidates are skipped without changing the order of remaining unit assignments.
- If the map cannot provide a target for every unit, the result contains only the stable subset of navigable assignments; it never stacks units or invents an out-of-bounds target.
- The resolver is pure, immutable at its boundary, and independent of wall-clock time, RNG, renderer, protocol, and transport.
- Snapshot/replay behavior remains deterministic because the resolver depends only on the sorted IDs, click tile, and canonical navigation grid.
- Player-facing movement around obstacles remains a later vertical slice; this packet does not mark gameplay navigation complete.

## Design

- Reuse the existing spiral source in `domain/formation.ts` and add a tile-space resolver that queries the authoritative `NavigationGrid`.
- Keep fixed-point movement offsets and tile-space navigation targets separate until the movement/path request integration defines their conversion contract.
- Return fresh frozen destination records; do not expose grid internals or mutate the input IDs.
