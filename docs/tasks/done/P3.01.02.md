# P3.01.02 - A* Pathfinding

## Task

- ID: `P3.01.02`
- Objective: Implement deterministic A* over the Phase 3 navigation grid.
- Why: Movement needs optimal, reproducible routes around water, resources, and
  future dynamic footprints.
- Scope: `packages/pathfinding`, focused unit tests, and the pathfinding public
  API contract.
- Non-goals: Incremental scheduling, simulation state, collision, vision,
  protocol, renderer, or browser gameplay.

## Contract

- Orthogonal movement costs `1024`.
- Diagonal movement costs `1448`.
- Heuristic is integer octile distance.
- Diagonal corner cutting is forbidden.
- Open entries are ordered by `f`, then `h`, then `tileIndex`.
- Blocked destinations resolve to the nearest walkable tile by octile distance,
  then `tileIndex`.
- Results are `FOUND`, `UNREACHABLE`, or `INVALID`.
- Invalid starts and empty maps fail explicitly and never throw during search.
- Repeated identical inputs return identical paths, costs, destinations, and
  expansion counts.

## Validation

- Unit tests cover optimal paths, walls, corner cutting, blocked destinations,
  unreachable targets, invalid starts, and repeatability.
- Public API test covers `findPath` and typed result registries.
- `@rts/pathfinding` typecheck and build pass.
- Repository `verify:fast` passes.

## Completion

This is a pure technical foundation. Incremental search and player-facing
movement are delivered by `P3.02.01` and later packets.
