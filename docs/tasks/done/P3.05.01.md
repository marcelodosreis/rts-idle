# Task Packet: P3.05.01 Spatial Index

## Task

- ID: `P3.05.01`
- Objective: add deterministic spatial queries for simulation entities without exposing mutable index state.
- Why: collision and the later vision/targeting systems need bounded candidate queries instead of exhaustive world scans.
- Scope: `packages/pathfinding` generic spatial index, simulation world-index adapter, unit tests, public API documentation.
- Non-goals: collision resolution, vision, targeting, snapshot persistence of the derived index, or browser UI.

## Contract

- The pure pathfinding package exposes an immutable spatial index over integer
  axis-aligned bounds.
- Index entries have a unique numeric entity ID and inclusive integer bounds.
- Queries return every intersecting entry exactly once, sorted by entity ID;
  bucket order and insertion order must not affect results.
- Invalid cell sizes, bounds, and duplicate IDs fail closed.
- The simulation adapter indexes positioned units by their deterministic logical
  radius and buildings by their rectangular footprint.
- The index is derived inside the simulation step and never becomes canonical
  state; snapshots restore the world and rebuild the index when needed.
- No clock, random source, DOM, renderer, transport, or mutable reference leaks
  across the package boundary.

## Design

- `packages/pathfinding/src/spatial-index.ts` owns the generic immutable uniform
  grid and broad-phase rectangle query.
- `packages/simulation/src/spatial/world-spatial-index.ts` translates ECS
  components into unit/building index entries and keeps game geometry in the
  simulation package.
- Collision code consumes query candidates and performs narrow-phase checks;
  the index does not know about units, buildings, or gameplay rules.
