# P3.08.01 - Filtered Observations and Events

## Task

- ID: `P3.08.01`
- Objective: Filter snapshots and events by player visibility while keeping the match playable through the real server.
- Why: Hidden entities, resources, orders, and combat events must not cross the protocol boundary.
- Scope: `packages/simulation`, `packages/protocol`, `apps/server`, `packages/renderer`, `apps/web`, and focused tests.
- Non-goals: Final fog artwork, minimap work, targeting, projectiles, and area damage.

## Contract

- The server produces immutable player observations from authoritative state and player vision.
- Hidden entities and hidden event payloads are absent, not redacted with usable coordinates.
- Visible data remains complete and keeps canonical identifiers and ordering.
- Natural interaction: move the player's unit between an enemy's visible and hidden regions.
- Success feedback: the enemy appears only while visible and disappears from the client's observation after leaving vision.
- Blocked/error feedback: malformed filtered observations are rejected and never rendered.
- Browser target: `tests/e2e/match/filtered-observations-playable.spec.ts` through the real server.

## Design

Keep authority and filtering on the server boundary. The browser renders filtered observations and never reconstructs hidden state. Protocol guards must use typed codecs and fail closed.

## Tests and validation

- Unit tests for visible completeness, hidden absence, ordering, and immutability.
- Simulation tests proving filtering does not change authoritative outcomes or hashes.
- Protocol contract tests for malformed and hidden payloads.
- Browser E2E in Chromium and Firefox covering appearance, disappearance, and hidden-event absence.
- `pnpm run verify`

## Player-facing completion

- [x] The player can reach the feature through the match screen.
- [x] The player can reveal and hide a scripted enemy through natural movement.
- [x] Entity/event visibility changes are visible and understandable.
- [x] The real server path is covered by browser E2E.

## Acceptance and stop conditions

- [x] No hidden data crosses the protocol boundary.
- [x] Visible data remains complete and immutable.
- [x] The player-facing flow and E2E pass in both required browsers.
