# Task Packet: VS-01 — Economy v0

## Task ID

`VS-01`

## Objective

Create the first minimal deterministic resource loop: Worker → Mineral Node →
Gather → Carry → Return to Base → Deposit → owning player's minerals increase.

## Why

Phase 1 has deterministic movement, orders, combat, players, snapshots, and
hashing but no economy. VS-01 provides the smallest playable economy slice on
those foundations and satisfies Phase 2 deliverables P2.01 and P2.02 without
pulling construction or production forward.

## Tech Stack and Commands

- TypeScript, Vitest, the custom Map-backed ECS, integer fixed-point movement,
  canonical binary snapshots, SHA-256 state hashes.
- Focused: `pnpm vitest run tests/simulation/economy-v0.test.ts`
- Contracts: `pnpm run test:contracts`

## Code Style

Use explicit domain data and deterministic tie-breaks:

```ts
interface CargoData {
  readonly amount: number
  readonly capacity: number
}

const orderedWorkers = state.world.aliveIds()
```

No generic resource registry, strategy interface, clock abstraction, or future
economy hierarchy is introduced.

## Implementation Requirements

1. `pawn` + `Cargo` identifies a Worker eligible for `GATHER`.
2. `MineralNode.remaining`, `Cargo.amount/capacity`, and the `GATHER` order's
   node/Base references, phase, and progress are canonical simulation state.
3. `Base` is a marker on an owned positioned entity and is the only valid
   Economy v0 deposit point.
4. `GATHER` validates all selected workers and the target node before mutation.
5. A valid command replaces each worker's current order and moves it to the
   target node via the existing `Movement` component.
6. One mineral transfers from node to cargo after 20 uncontested gather ticks;
   capacity is 10 and node remaining never becomes negative.
7. Only one worker gathers from a node per tick; lowest entity ID wins.
8. A full worker chooses the nearest valid owned Base by squared distance, then
   entity ID, travels there, deposits all cargo into `PlayerState.gold`, and
   repeats while the node remains valid and non-empty.
9. If no valid owned Base exists, cargo is retained in a canonical waiting
   state and return resumes if a Base later becomes valid.
10. Worker death removes its cargo with the entity. Replacing `GATHER` stops the
    loop without converting cargo into wallet minerals.
11. Node + cargo + deposited wallet minerals are conserved for the scenario.
12. Economy runs after movement and before combat; all existing relative system
    ordering remains unchanged.
13. Snapshots/restore preserve every economy phase and continue identically.
14. Economy state participates in canonical hashing and deterministic replay.
15. The simulation version and pinned golden bytes/hash change deliberately.

## Testing Strategy

- Unit: economy component/order codec defaults, values, and ECS cleanup.
- Contract: accepted `GATHER` shape; rejection of missing/foreign/non-worker/
  non-node targets; atomic hash equality against a no-command control.
- Simulation: full loop, deposit timing, repeat trip, exhaustion, contention,
  Base selection, waiting, cancellation, and death cargo loss.
- Determinism: equal command streams hash equally; snapshot continuation from
  each active phase remains equal; economy-state changes alter hashes.
- Architecture: public additions are explicit; isolation/import barriers stay
  green.

## Boundaries

- **Always:** integer arithmetic, ascending-ID iteration, explicit tie-breaks,
  validation before mutation, tests first, focused validation after each slice.
- **Ask/review first:** change the stated constants, rename the wallet across
  packages, or choose a pipeline position different from ADR-013.
- **Never:** add Energy, placement, construction, production, supply,
  pathfinding, collision, fog, AI, multiplayer rooms, new factions, UI work, or
  speculative generalized economy abstractions.

## Acceptance Criteria

- [x] Worker gathers only from a valid Mineral Node.
- [x] Cargo amount/capacity and gather phase/progress are deterministic state.
- [x] Worker returns cargo only to a valid owned Base.
- [x] Wallet minerals increase only when cargo is deposited.
- [x] Node, cargo, and wallet obey resource conservation and non-negativity.
- [x] Snapshot/export/restore preserves and resumes the loop exactly.
- [x] Economy state changes canonical hashes; equal runs remain hash-equal.
- [x] Existing invariants, public APIs, architecture barriers, and tests remain valid.
- [x] Focused validation and `pnpm run verify` pass; E2E was run for the browser surface.

## Non-Goals

- Energy or multiple resource types.
- Building placement, construction, production, supply, repair, or research.
- Pathfinding, collision, fog of war, strategic AI, or multiplayer rooms.
- Renderer/HUD changes, new faction content, and future-facing abstractions.

## Stop Conditions

- Stop after every acceptance criterion and completion gate passes.
- Stop and request review if the approved canonical/pipeline assumptions must
  change.
- Do not expand into later Phase 2 deliverables.
