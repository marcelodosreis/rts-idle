# Task Packet: P2.07 — Production Queue and Unit Training

## Task

- ID: `P2.07` / historical alias `PROD-001-002`
- Objective: add deterministic Base/Barracks production from `TRAIN` acceptance through unit spawn.
- Why: Phase 2 currently has completed producers and supply accounting but no player-facing unit production.
- Scope: shared, game-data, protocol, simulation, server projection, tests, and simulation documentation.
- Non-goals: rally points, blocked-exit retry/recovery, production cancellation, producer destruction, repair, research, and economic integration. The production roster includes Pawn, Warrior, and Archer with producer-specific training.

## Contract

- Base trains `pawn`; Barracks trains `warrior` and `archer`.
- Pawn takes 100 ticks, Warrior takes 200 ticks, and Archer takes 300 ticks.
- Warrior costs 100 minerals. Archer costs 125 minerals.
- A completed owned Base or Barracks accepts at most five items.
- Minerals and one supply per item are reserved atomically on `TRAIN` acceptance.
- One item advances per producer; production pauses while `usedSupply + reservedSupply > supplyCap`.
- Completion spawns the unit at the deterministic producer exit when free. An occupied exit retains `COMPLETED_WAITING` without overlap.
- Reserved supply becomes used supply only after spawn.
- Queue, progress, reservations, and player `reservedSupply` are canonical and deterministic.
